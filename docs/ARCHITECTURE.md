# Marden backend architecture

Marden is deep coverage of AI infrastructure debt and the facilities behind it. The backend collects public records, stores every file raw, turns records into sourced facts, runs models on those facts, and serves precomputed screen documents to the web app with live updates.

Specs live in `handoff/` (specs 00–27, `api/types.ts`, `api/endpoints.md`). `handoff/specs/22-data-agents-models.md` and `21-tech-stack.md` are the source of truth for data flow. This file says how this repo implements them.

## Hard rules

1. **Real data only.** The API never serves fixtures, sample numbers or placeholders. A value nobody has sourced is `null` (shown as n/d). `handoff/fixtures/` may be read by tests only.
2. **No stand-ins for blocked sources.** If a source is unreachable, blocked by its terms, or needs a missing credential, the collector records the failure on its `source` row and returns. It never writes made-up rows.
3. **Raw first.** Fetch → store the bytes (`marden.core.rawstore`) → insert `document` → parse. Parsers read from the raw store, so anything can be re-parsed.
4. **Every value is sourced.** Each fact has `tag` (F filed, R reported, M model), `source_name`, `source_url`, `valid_from` (as-of) and, for M, `method_version`. Extracted facts carry the exact `quote`.
5. **Safe reruns.** Every write is idempotent: `fact.dedupe_key`, `price_obs.dedupe_key`, `event.dedupe_key`, `document (source_id, url, sha256)`.
6. **Never overwrite history.** New values are new rows. `fact_current` picks the current value; `fact_asof(date)` answers what Marden knew on a date.
7. **Agents read, code computes.** LLM extraction produces candidate facts with quotes; models (Python) compute every number.
8. **Polite collection.** Declared `SEC_USER_AGENT`, SEC < 10 req/s, per-host rate limits, caching, and each site's terms checked and noted on its `source` row (`terms_note`, `blocked`).

## Layout

```
db/migrations/        dbmate SQL migrations (the schema is the contract)
db/schema.sql         generated by dbmate
services/             Python 3.12+ package `marden` (uv): collectors, extraction, models, read models, worker
  marden/core/        config, db, rawstore, http, facts, events, heartbeats, queue
  marden/seed/        loaders for marden_data_2026-10-20.zip (MARDEN_SEED_DIR)
  marden/collectors/  one module per source: <source>.py (fetch, store raw, parse, write)
  marden/extraction/  document schemas, extractor + verifier (Claude API), quote checks, review routing
  marden/models/      status rules, cushion, price, mark gap, recovery, stress, risk rank, GPU, capacity, ...
  marden/readmodels/  one builder per screen document -> read_model rows + stream events
  marden/worker.py    Procrastinate worker: task registry and periodic schedules
  tests/
apps/api/             Node 22 + TypeScript + Fastify: serves /api/* from read_model, SSE from stream_event
docs/                 this file, DATA_SOURCES.md (one-pager for fund vendor reviews), runbooks
```

## Data flow

```
collector ──raw bytes──> rawstore + document
    │ structured sources (N-PORT XML, XBRL, EIA, ERCOT, FRED, STAC): parse in code -> facts (published) / price_obs / holding / event
    └ documents needing reading (8-K, EX-10, permits, agendas, dockets): document.extract_state='queued'
extraction worker ──Claude API──> candidate facts with quotes -> verifier -> publish | review_item
published fact ──> read_model_dirty(view,key) + model triggers
model worker ──> model_output (+ M facts / marden price_obs) ──> read_model_dirty
read model builder (every 30 s for dirty keys; nightly for all) ──> read_model row ──> stream_event (NOTIFY marden_stream)
API ──SELECT doc FROM read_model──> app;  GET /api/stream LISTENs on marden_stream and replays from Last-Event-ID
```

## The fact store

- `subject_type` ∈ `site, campus, building, plant, unit, instrument, entity, obligation, holding`; `subject_id` is that table's primary key.
- `field` names are snake_case and stable (e.g. `facility_mw`, `outside_date`, `coupon`, `maturity`, `amount_usd`, `status`). A field's value is JSON (number, string, ISO date, object).
- Status: `candidate` → `published` | `rejected`; superseding values are new rows, older rows stay.
- Publishing rules (spec 22): structured filed data that passes validators publishes directly. Extracted facts publish only when the verifier agrees and the fact is not material; otherwise a `review_item` is opened. Material facts (change a chain status, cushion band or alert) always wait for a person.
- Units: money in USD (not billions) unless the field name says otherwise; MW in MW; dates ISO; prices in percent of par.

## Read models

- `read_model(view, key, as_of, doc)`. Views are named after screens/endpoints: `completion` (key `all`), `sites` (`all`), `site_detail` (slug), `site_schedule` (slug), `site_tab:<tab>` (slug), `instruments` (`all`), `instrument_detail` (id), `dc_row` (campus id), `dc_detail` (campus id), `plant_row`, `plant_detail`, `payer` (slug), `risk_list` (week start), `home` (`all`), `track_record` (`all`), `obligations` (`all`), `leases` (`all`), `project_file` (slug), `search_index` (`all`) ...
- The `doc` is exactly the response type in `handoff/api/types.ts`. The API adds only per-user data (watchlist, alerts) and filtering.
- Builders mark nothing themselves; `marden.core.facts.publish()` marks dependents dirty via `marden.readmodels.deps`.
- One row per view/key per day keeps snapshots for `?asOf=`.

## Queue and schedule

Procrastinate on the same Postgres. Collectors, extraction, models and read-model rebuilds are tasks; periodic tasks implement the cadences in spec 22 ("What runs when"). Each source run is wrapped in `marden.core.heartbeat.run(source_id)` which writes `source_run` and updates `source.last_ok_at`, so `/api/sources/health` and the stale-data footer work.

## Live updates

Write a `stream_event` row (payload = a `StreamEvent` from types.ts, optional `org_id`); its trigger sends `NOTIFY marden_stream, '<id>'`. The API keeps one LISTEN connection, loads the row and pushes it to connected clients (scoped to their org), with `id:` set to the row id for `Last-Event-ID` replay. Heartbeat comment every 25 s.

## Auth (spec 23)

Clerk session tokens verified by the API; Marden roles owner/admin/member/viewer plus staff; every route declares a permission and the server refuses to start if a route has none. Until Clerk keys exist, `MARDEN_AUTH_MODE=dev` gives one local owner+staff user in org `dev`; it is refused when `NODE_ENV=production`.

## Environment

See `.env.example`. Local development: Postgres 16 + PostGIS on localhost (`postgres://marden:marden@localhost:5432/marden`); raw store on local disk under `MARDEN_RAW_DIR` until R2 keys exist. Neon and R2 replace them by setting `DATABASE_URL` and `R2_*`.

## Conventions

- Python: 3.12+, `ruff` + `pytest`, type hints, files ≤ 400 lines, snake_case modules. psycopg 3 (sync, pooled). httpx for HTTP.
- TypeScript: strict, ESLint, vitest, files ≤ 300 lines, kebab-case files.
- No throwaway names (`_v2`, `old`, `new`, `final`, `tmp`). No secrets or `.env` files in git. No data files over 512 KB in git.
- Tests that need the database use the local Postgres and a throwaway schema or transaction rollback; tests never mock away the thing they claim to test.
