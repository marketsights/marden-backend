# Marden backend architecture

Marden is deep coverage of AI infrastructure debt and the facilities behind it. The backend collects public records, stores every file raw, turns records into sourced facts, runs models on those facts, and serves precomputed screen documents to the web app with live updates.

Specs live in `handoff/` (specs 00–27, `api/types.ts`, `api/endpoints.md`). `handoff/specs/22-data-agents-models.md` and `21-tech-stack.md` are the source of truth for data flow. This file says how this repo implements them.

## Hard rules

1. **Real data only.** The API never serves fixtures, sample numbers or placeholders. A value nobody has sourced is `null` (shown as n/d). `handoff/fixtures/` may be read by tests only.
2. **No stand-ins for blocked sources.** If a source is unreachable, blocked by its terms, or needs a missing credential, the collector records the failure on its `source` row and returns. It never writes made-up rows.
3. **Raw first.** Fetch → store the bytes (`marden.core.rawstore`) → insert `document` → parse. Parsers read from the raw store, so anything can be re-parsed.
4. **Every value is sourced.** Each fact has `tag` (F filed, R reported, M model), `source_name`, `source_url`, `valid_from` (as-of) and, for M, `method_version`. Extracted facts carry the exact `quote`.
5. **Safe reruns.** Every write is idempotent: `fact.dedupe_key`, `price_obs.dedupe_key`, `event.dedupe_key`, `document (source_id, url, sha256)`.
6. **Never overwrite history.** New values are new rows. `fact_current` picks the current value; `fact_asof(date)` answers what Marden knew on a date.
7. **Agents read, code computes.** LLM extraction produces candidate facts with quotes; models (Python) compute every number.
8. **Polite collection.** Declared `SEC_USER_AGENT`, SEC < 10 req/s, per-host rate limits, caching, and each site's terms checked and noted on its `source` row (`terms_note`, `blocked`).
9. **Licence flags.** Sources collected without a commercial licence (finra.org TRACE, Börse Frankfurt, Yahoo Finance) write exact `source_name`s flagged `unlicensed-commercial` in `marden.core.licensing`; `MARDEN_SHOW_UNLICENSED_PRICES` (default true) is the switch that hides them (docs/methods/licensing.md). Bot protection is never evaded: a challenge, login wall, 401/403 or repeated 429 is recorded on the source and the run stops.

## Layout

```
db/migrations/        dbmate SQL migrations (the schema is the contract)
db/schema.sql         generated by dbmate
services/             Python 3.12+ package `marden` (uv): collectors, extraction, models, read models, worker
  marden/core/        config, db, rawstore, http, facts, events, heartbeats, queue, licensing
  marden/seed/        loaders for marden_data_2026-10-20.zip (MARDEN_SEED_DIR)
  marden/collectors/  one module per source: <source>.py (fetch, store raw, parse, write)
  marden/extraction/  document schemas, extractor + verifier (Claude API), quote checks, review routing
  marden/models/      status rules, cushion, price, mark gap, recovery, stress, risk rank, GPU, capacity, ...
  marden/readmodels/  one builder per screen document -> read_model rows + stream events
  marden/worker.py    Procrastinate worker: task registry and periodic schedules
  tests/
apps/api/             Node 22 + TypeScript + Fastify: serves /api/* from read_model, SSE from stream_event
docs/                 this file, DATA_SOURCES.md (one-pager for fund vendor reviews), runbooks
```

## Data flow

```
collector ──raw bytes──> rawstore + document
    │ structured sources (N-PORT XML, XBRL, EIA, ERCOT, FRED, STAC): parse in code -> facts (published) / price_obs / holding / event
    └ documents needing reading (8-K, EX-10, permits, agendas, dockets): document.extract_state='queued'
extraction worker ──Claude API──> candidate facts with quotes -> verifier -> publish | review_item
published fact ──> read_model_dirty(view,key) + model triggers
model worker ──> model_output (+ M facts / marden price_obs) ──> read_model_dirty
read model builder (every 30 s for dirty keys; nightly for all) ──> read_model row ──> stream_event (NOTIFY marden_stream)
API ──SELECT doc FROM read_model──> app;  GET /api/stream LISTENs on marden_stream and replays from Last-Event-ID
```

## The fact store

- `subject_type` ∈ `site, campus, building, plant, unit, instrument, entity, obligation, holding`; `subject_id` is that table's primary key.
- `series` holds time series that are not instruments (rate curves, rates, spread indexes): `subject_id` is the series id (`ust_par_10y`, `sofr`, `ice_bofa_us_hy_oas`), field `value`, one fact per observation date (`valid_from`); licence facts sit on the same subject (`notice`, `display_allowed`, `copyright_notice`).
- Capacity auction results are `series` too, one subject per auction and zone: `capacity:<iso>:<zone>:<period>` (`capacity:pjm:dom:2028-2029`, `capacity:pjm:rto:2026-2027-3ia`, `capacity:isone:rop:2027-2028`) with `clearing_price` (USD/MW-day; `clearing_price_native` in the operator's unit), `cleared_mw`, `auction_name`, `auction_date`, `delivery_start`, `delivery_end` and operator extras, valid_from = the results' publication date (`marden/collectors/capacity_common.py`). Which zone a site, campus or plant is in: `capacity_market` / `capacity_zone` / `capacity_market_reason` (model `capacity_zones`, tag M).
- `queue_project` holds ISO/RTO interconnection queue entries (generation, transmission and large-load requests): `subject_id` is `queue_project.id` = `<iso>:<queue id>` (`pjm:AE1-070`, `nyiso:1670`). Collectors write only changed values (`marden.collectors.iso_queue`); `linked_site` / `linked_campus` / `linked_plant` (tag M, queue-match@0.1, with evidence) tie an entry to our subjects, status and COD changes become `interconnection` events on them, and large loads also land on the subject as `large_load_queue_<iso>`. Non-RTO transmission providers use the same model with their own prefix (`bpa:L0705`; no `iso` fact, `balancing_authority` instead); the LBNL Queued Up compilation is tag R on separate subjects `lbnl:<entity>:<queue id>` (`operator_entry` points to the operator's own entry), so it never displaces an operator's current value. Coverage per region: `docs/grid-coverage.md`.
- Grid regions are identity tables: `grid_region` (interconnections, ISO/RTOs, balancing authorities, retail territories, TSOs; boundaries from HIFLD, codes from EIA-930/861) and `us_county` (Census county polygons). `grid_join` writes `interconnection`, `iso`, `balancing_authority`, `utility` and `utility_territories` (tag F, source HIFLD) on campuses, buildings, sites and plants, placing each by its own point, a stand-in point (its campus; a site's one approved linked campus; a plant's one served campus) or its county polygon; overlaps, county splits, retired BAs and interconnection seams become candidates with a review item.
- `eia_generator` holds EIA-860M generators (`marden.collectors.eia_860m`): `subject_id` is `<EIA plant id>_<generator id>` (`3122_CA5`); planned generators in data-center states and every generator once tracked, tag F, `valid_from` = the report month's end, change-only: `generator` (descriptor), `status` (EIA code, or `retired` / `canceled_or_postponed`), `planned_online` / `operating_month` / `retired_month` (`YYYY-MM`). The rows are the planned-vs-actual history the cushion model reads; slips are only counted in run meta. Matched `plant` subjects get `planned_online` and `eia_status` ({generator id: value}); the plant's own `status` keeps the PlantStatus vocabulary.
- Company financials (`marden.collectors.sec_xbrl`, SEC XBRL companyfacts) are `entity` facts, tag F, one per period and value, `valid_from` = period end: durations `<base>_<n>m_usd` for 3/6/9/12-month periods (`operating_cash_flow`, `capex`, `revenue`, `contract_revenue`, ...), instants `<base>_usd` (`cash`, `total_debt`, `long_term_debt`, `operating_lease_liability`, `finance_lease_liability`, `construction_in_progress`, `ppe_net`, `unrecorded_purchase_obligation`, ...), share counts `shares_outstanding` (cover page) and `common_shares_outstanding`; `public_date` = the filing date that first made a period's values public. `quote_loc` names the XBRL concept and filing, `quote` is the companyfacts record; a restated value is a new fact from the restating filing.
- `field` names are snake_case and stable (e.g. `facility_mw`, `outside_date`, `coupon`, `maturity`, `amount_usd`, `status`). A field's value is JSON (number, string, ISO date, object).
- Status: `candidate` → `published` | `rejected`; superseding values are new rows, older rows stay.
- Publishing rules (spec 22): structured filed data that passes validators publishes directly. Extracted facts publish only when the verifier agrees and the fact is not material; otherwise a `review_item` is opened. Material facts (change a chain status, cushion band or alert) always wait for a person.
- Units: money in USD (not billions) unless the field name says otherwise; MW in MW; dates ISO; prices in percent of par.
- Reads: the current value comes from `fact_current`, what Marden knew on a date from `fact_asof(date)`. Only the writers touch `fact` directly; builders read through `marden.readmodels.known_facts`, and the API's one fact lookup (air permit numbers for search and the data-center/plant search box) goes through the same two.

## Read models

- `read_model(view, key, as_of, doc)`: one precomputed document per screen piece. The `doc` is exactly the response type in `handoff/api/types.ts`; the API adds only per-user data (watchlist, unread alerts) and filtering, and never recomputes a value.
- Snapshots: one row per view/key per day (US Eastern). The API serves the latest snapshot, or with `?asOf=` the latest on or before that date. Today's snapshot is built from `fact_current`. `rebuild_all(view, as_of=<past day>)` backfills a past day from `fact_asof(day)` (builders read facts with `known_facts` and date other reads with `build_date()`), sends no live event and leaves today's dirty marks. A snapshot dated after today is refused.
- Builders mark nothing themselves: the writers (`FactWriter`, `PriceWriter`, `EventWriter`, `HoldingWriter`) mark dependents dirty through `marden.readmodels.deps` when a value is published; the risk-list, backtest and GPU-index tasks call `mark_dirty` for their own views.
- A keyed GET answers 404 when the id is not in its identity table, and 503 `{error: 'not_ready', view, key}` while the read model has not been built.
- View names live in `marden.readmodels.views.VIEWS`. Builders, dependencies and dirty marks are checked against it; `services/tests/test_readmodels.py` checks it against the table below, and `apps/api/test/views.test.ts` checks every API read-model route against the same table.

## Queue and schedule

Procrastinate on the same Postgres. Collectors, extraction, models and read-model rebuilds are tasks; periodic tasks implement the cadences in spec 22 ("What runs when"). Each source run is wrapped in `marden.core.heartbeat.run(source_id)` which writes `source_run` and updates `source.last_ok_at`, so `/api/sources/health` and the stale-data footer work.

## Live updates

Write a `stream_event` row (payload = a `StreamEvent` from types.ts, optional `org_id`); its trigger sends `NOTIFY marden_stream, '<id>'`. The API keeps one LISTEN connection, loads the row and pushes it to connected clients (scoped to their org), with `id:` set to the row id for `Last-Event-ID` replay. Heartbeat comment every 25 s.

## Auth (spec 23)

Clerk session tokens verified by the API; Marden roles owner/admin/member/viewer plus staff; every route declares a permission and the server refuses to start if a route has none. Until Clerk keys exist, `MARDEN_AUTH_MODE=dev` gives one local owner+staff user in org `dev`. Dev mode is refused unless `NODE_ENV` is `development` or `test`, and on any Railway environment (`RAILWAY_ENVIRONMENT*` set); `buildApp` re-checks this, so a hand-built config cannot bypass it.

Per-product access (`docs/access-control.md`): Clerk is identity only. Firms hold products (`org_product`: plan, seats, status, dates) and members hold a role per product (`member_product_role`); each product's role -> permission matrix is code in `apps/api/src/auth/products/<id>.ts`. `membership.role` is the org-level admin role (team and product assignments). An org or member with no live product role gets 403 `no_product` on every data route; `/api/me` lists the org's live products and the caller's effective permissions. Dev mode gives org `dev` product `marden` (paid) with the dev user as owner.

## Environment

See `.env.example`. Local development: Postgres 16 + PostGIS on localhost (`postgres://marden:marden@localhost:5432/marden`); raw store on local disk under `MARDEN_RAW_DIR` until R2 keys exist. Neon and R2 replace them by setting `DATABASE_URL` and `R2_*`.

## Conventions

- Python: 3.12+, `ruff` + `pytest`, type hints, files ≤ 400 lines, snake_case modules. psycopg 3 (sync, pooled). httpx for HTTP.
- TypeScript: strict, ESLint, vitest, files ≤ 300 lines, kebab-case files.
- No throwaway names (`_v2`, `old`, `new`, `final`, `tmp`). No secrets or `.env` files in git. No data files over 512 KB in git.
- Tests that need the database use the local Postgres and a throwaway database (Python), a throwaway schema (API) or transaction rollback; tests never mock away the thing they claim to test.
